# Plan: Async IDC (outbox tables) for C# modules — issue SpacetimeDBPrivate#4223

## Context

Rust and TypeScript modules can already send asynchronous inter-database calls (IDC). A sending reducer inserts a row into an **outbox table**. The host then delivers that row as a call to a reducer in another database, and can run an `on_result` reducer back in the sending database. C# has none of this, and the docs call it a limitation. The goal is full parity:

- receiver bindings from `spacetime generate --bindings module --lang csharp`;
- `[Table(Outbox = typeof(...))]`, `[Target]`, `[Param("...")]` and `[OnResult(typeof(Row))]` in the C# source generator;
- the V10 outbox metadata;
- tests, docs and an example.

**The host side is done and language-agnostic.**
- Delivery encodes the arguments host-side: `idc_actor.rs::encode_reducer_args` concatenates the BSATN of each `arg_columns` column.
- `on_result` args are `bsatn(row) ++ bsatn(Result<(), String>)` (`idc_actor.rs:826`).
- Validation lives in `crates/schema/src/def/validate/v10.rs:1206-1344`.

So the C# module only has to emit correct `RawOutboxDefV10` entries. That type and the `Outboxes` section variant are already autogenerated in `Runtime/Internal/Autogen/RawOutboxDefV10.g.cs` and `RawModuleDefV10Section.g.cs`. **No Rust host or schema changes should be needed.**

### Decisions taken

- **Parameter override:** `ParamAttribute(string name)`, so it's written `[Param("name")]`. The string is the receiver's **canonical** parameter name, compared verbatim (case-sensitive, like Rust).
- **Callback names starting with `On`:** `[OnResult]` reducers are exempt from `ReducerReservedPrefix`, so `OnPingResult` is allowed. They're forced private and stay out of client bindings unless the user generates with `--include-private`.
- **Generated outbox shortcut:** `[Gw.Outbox.ReceivePing(...)] partial struct X {}` gets its own PR in the last phase. Everything before that works with manual declarations.
- **Matching rule:** a column matches a receiver parameter when its canonical name equals the parameter's canonical name and the C# types are identical.
  - The canonical name is the `[Param]` override if present. Otherwise it's the field name run through the module's `CaseConversionPolicy` (default snake_case).
  - Column order doesn't matter, and extra columns are allowed.
  - The message ID and target columns may also supply parameters.

## Generated C# receiver bindings: shape

The CLI writes them to `<sender>/remote_bindings/<dep>/`. The default `.csproj` globbing compiles them into the module automatically. The default namespace is `RemoteBindings.<PascalDep>`, which a new `namespace` field on dependency entries can override. That replaces today's shared `SpacetimeDB.Types`, which would make two dependencies collide. Everything references `global::SpacetimeDB.*` so receiver types can't shadow builtins.

```csharp
namespace RemoteBindings.GameWorld;

// Distinct per dependency; on the wire this is identical to SpacetimeDB.Identity.
public readonly partial struct Identity : IEquatable<Identity> {
    public readonly global::SpacetimeDB.Identity Value;
    public Identity(global::SpacetimeDB.Identity v) { Value = v; }
    public static explicit operator Identity(global::SpacetimeDB.Identity v) => new(v);
    public static implicit operator global::SpacetimeDB.Identity(Identity v) => v.Value;
    public readonly struct BSATN : global::SpacetimeDB.BSATN.IReadWrite<Identity> { /* delegates to Identity.BSATN, same AlgebraicType */ }
}

[global::SpacetimeDB.Type(Name = "game_world.Details")]   // dependency-scoped schema name
public partial struct Details { ... }

public static partial class Reducers {
    [global::SpacetimeDB.Internal.RemoteReducer("admit_player", "<sig-hash-hex>")]
    public sealed class AdmitPlayer {
        // One field per receiver param, in receiver order; carries canonical name + C# type.
        [global::SpacetimeDB.Internal.RemoteParam("name")] public string Name = default!;
    }
}
```

The source generator reads these from the `typeof(...)` symbol. Bindings are checked-in source, not generator output, so the symbols are visible to it. It reads three things:
- the attribute constants, for the reducer name and hash;
- the field order, names and types, for the parameters;
- `Identity`, located as `<containing namespace>.Identity`, for the target check.

## Phases / PRs

All of this is **Core** tier. No `.deep` paths are touched except one optional test PR, noted in Phase 4.

### PR 1: Runtime and generator plumbing (crates/bindings-csharp)

1. **Scoped type names.**
   - Add `Name` to `SpacetimeDB.TypeAttribute` (`BSATN.Runtime/Attrs.cs:10`).
   - Make the BSATN Type generator (`BSATN.Codegen/Type.cs`) pass it through, for example as a static `TypeName` on the generated `BSATN` struct or an attribute lookup.
   - `ModuleBuilder.MakeScopedTypeName` (`Runtime/Internal/ModuleBuilder.cs:65-105`) splits on `.` into `scope + name` when it's set, and falls back to `GetFriendlyName`.
2. **Outbox registration in `ModuleBuilder`.**
   - Add an `outboxDefs` list and `RegisterOutbox(RawOutboxDefV10)`.
   - Add `SetOutboxOnResult(table, reducer)`, which errors on an unknown table or a duplicate callback. Link the callbacks in `BuildModuleDefinition()` after all tables and reducers are registered, as Rust does at `rt.rs:1223`.
   - Emit a `RawModuleDefV10Section.Outboxes` section only when the list is non-empty.
   - Add a hex-to-`U256` helper for the signature hash. The 32 hex-decoded bytes are the little-endian bytes of the U256 (`crates/sats/src/hash.rs:14`).
3. **New attributes in `Runtime/Attrs.cs`.**
   - `TableAttribute.Outbox` (`System.Type?`).
   - `TargetAttribute` and `ParamAttribute(string name)`, both column attributes with an optional `Table =` like the existing ones.
   - `OnResultAttribute(System.Type row)`.
   - `Internal.RemoteReducerAttribute(name, signatureHash)` and `Internal.RemoteParamAttribute(name)`.
4. **`typeof` support in `ParseAs<T>`** (`BSATN.Codegen/Utils.cs:215-260`). Today it would throw on a `TypedConstantKind.Type` argument. Skip Type-kind arguments in `ParseAs` and read them by hand, following the existing pattern at `Codegen/Module.cs:2656-2661`.
5. **Share the canonical-name conversion.** Compile `Runtime/Internal/CanonicalName.cs` into `Codegen.csproj`, the same way `Attrs.cs` is linked at `Codegen.csproj:39`. The generator can then apply `CaseConversionPolicy` at compile time.

**Tests:** Codegen.Tests snapshots for a `[Type(Name=...)]` type, and a Runtime.Tests unit test for hex→U256.

### PR 3: Source generator for outbox tables and `on_result` (crates/bindings-csharp/Codegen)

1. **`TableAccessor` (`Module.cs:285-324`).** Read `Outbox` as an `INamedTypeSymbol`. Store only equatable strings and ints in the declaration record, because the `CheckCacheWorking` test catches cached symbols.
2. **Validation.** New diagnostics are appended at the end of `Codegen/Diag.cs`, because IDs are positional.
   - The `Outbox` type must carry `[RemoteReducer]`.
   - The table can't also be `Scheduled` or `Event`.
   - It needs exactly one `[PrimaryKey, AutoInc] ulong` column.
   - It needs exactly one `[Target]` column, whose type is the receiver's `Identity`. That's `SymbolEqualityComparer` against `<outbox type's namespace>.Identity`, so a plain `SpacetimeDB.Identity` or another dependency's `Identity` is rejected.
   - Each `[RemoteParam]` must have exactly one matching column, with a "no column matching remote reducer parameter `x`" or "multiple columns…" error.
   - The matched column's type must be identical to the parameter's.
   - `[Param]` without `Outbox` is an error.
   - These run alongside the existing scheduled-table checks (`InvalidScheduledDeclaration`, `Diag.cs:130`).
3. **Emission** (handle struct, `Module.cs:1065-1122`).
   - Add `MakeOutboxDesc()`, which returns `RawOutboxDefV10(SourceName, RemoteReducer, TargetColumn, ArgColumns-in-receiver-order, null, U256FromHex(hash))` or `null`.
   - Call it from `ModuleBuilder.RegisterTable` (PR 1).
4. **Insert-only handle.** For outbox tables, generate a handle with only `Insert`, `Count`, `Iter` and **read-only** index accessors. Reuse the `ReadOnlyUniqueIndex` / `ReadOnlyIndexBase` path from `GenerateReadOnlyAccessors` (`Module.cs:1136`, `:882`). It has no `Delete`, `Clear` or `Update`, which mirrors Rust `OutboxTable` (`crates/bindings/src/table.rs:466`). Update `ValidateGeneratedNames` (`:657`).
5. **`[OnResult(typeof(Row))]` on `ReducerDeclaration` (`Module.cs:1799-1855`).**
   - The method must be `(ReducerContext, Row, Result<Unit, string>)`. `Row` must be a `[Table(Outbox=...)]` type with exactly one outbox table; otherwise, require `Table = "accessor"` on `[OnResult]` to disambiguate.
   - The reducer can't also be lifecycle or scheduled.
   - Allow at most one `[OnResult]` per outbox across the module. This needs a cross-declaration check in the `ModuleRegistration` stage, like the existing duplicate-name checks.
   - Exempt it from `ReducerReservedPrefix`.
   - Emit `builder.SetOutboxOnResult(nameof(accessor), nameof(reducer))`, linked at build time, and mark the reducer private.
6. **Tests.**
   - `fixtures/server/Lib.cs`: an outbox with a reordered target, a `[Param]` rename, an extra bookkeeping column, a zero-parameter receiver, and an `OnResult`.
   - `fixtures/diag/Lib.cs`: every new diagnostic.
   - Targeted STDB-id assertions in `Codegen.Tests/Tests.cs`, following `ViewInvalidReturnHighlightsReturnType` (`:1345`).
   - Receiver bindings for the fixtures are checked in next to them, in the PR 2 output format.

### PR 6: Generated outbox attribute

- For each reducer, the bindings emit `[Gw.Outbox.AdmitPlayer(Accessor = ..., Name = ...)]`. It's a sealed attribute deriving from `SpacetimeDB.Internal.GeneratedOutboxAttribute` and carries a reference to the reducer marker.
- The Module generator recognises it on an empty `partial struct` and synthesises the fields `MsgId` (`[PrimaryKey, AutoInc] ulong`), `Target` (`[Target] Gw.Identity`) and one field per parameter. It then feeds a synthetic `TableDeclaration` through the same path as PR 3.
- **Main design issue:** the separate BSATN `Type` generator can't see the synthesized fields. The fix is either to emit the `BSATN` serializer for these structs from the Module generator, or to have the Type generator recognise `GeneratedOutboxAttribute` itself. Decide this when the PR starts.
- Reject receivers that have a parameter named `msg_id` or `target`, as TypeScript does.
