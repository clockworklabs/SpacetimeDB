## Candidates

### TypeScript submodules: reusable database "libraries" under a namespace: HIGH
- What changed (exact, verified at v2.8.0):
  - A TS module can include another module in its `schema({...})` under an alias:
    ```ts
    import * as authLib from 'auth_lib';
    const spacetimedb = schema({ players, myauth: authLib });
    export default spacetimedb;
    ```
    All of the submodule's reducers, procedures, views, scheduled tables and HTTP handlers register automatically under the namespace. The import must be `import * as`. A default import throws `schema entry 'myauth' looks like a default import; use \`import * as myauth from '...'\` so the submodule can see the library's named reducer exports.`
  - Server-side access: `ctx.db.myauth.users…`. `ctx.as.myauth` narrows the context to call a submodule reducer, procedure or helper (e.g. `authLib.verifyToken(ctx.as.myauth, { token })`). HTTP handlers can delegate with `authLib.health(ctx.as.myauth, req)`.
  - Submodules can nest (`ctx.db.myauth.sessions.<table>`), and multiple submodules compose ("name collisions between submodules are impossible").
  - SQL and subscriptions use qualified names, e.g. `SELECT * FROM myauth.users`. Before, the SQL parser rejected these with "Multi-part names are not supported". Now it joins the parts into a namespaced name (`crates/sql-parser/src/parser/mod.rs`).
  - Wire and CLI names use a **dot**: `spacetime call my-database myauth.verify_token …`, `POST /v1/database/my-database/call/myauth.verify_token`. See `ModuleDef::reducer_by_name_with_module` using `split_once('.')` in `crates/schema/src/def.rs`, and the comment "Dot-qualified names (e.g. `lib.my_reducer`) route to submodules" in `crates/cli/src/subcommands/call.rs`.
  - Generated TS client bindings nest by namespace: `tables.myauth.users`, `reducers.myauth.verifyToken`, `procedures.myauth.sessionCount`, `conn.reducers.myauth.verifyToken(...)`. The query builder works on submodule tables and views.
  - Automigration handles submodule tables, views and indexes (adding or removing a submodule, or changing things inside it).
- Before this range: no submodules. There was no `submodule` field in `ModuleDef`, and multi-part SQL names were an error.
- Headline idea: "Build once. Mount anywhere." / "Databases, now composable."
- One-sentence description: A TypeScript module can now plug in another module, such as an auth or payments library, under its own namespace, with that module's tables, reducers, views and HTTP routes, and without name clashes.
- Visual idea: a "library" cube labelled `auth_lib` (tables `users`, `sessions`; reducer `verifyToken`) slides into a bigger cube `my-game` and snaps into a slot labelled `myauth`. A second one, `payments`, snaps in beside it. Code overlay: `schema({ players, myauth: authLib, payments: paymentLib })`. Then the client side: `useTable(tables.myauth.users)` lights the rows, and a terminal line `spacetime call my-game myauth.verify_token …` runs. Optional collision beat: both cubes have a `users` table, and the namespaces keep them apart (`users` vs `myauth.users`).
- Caveats (don't claim):
  - **TypeScript modules only.** Docs: "Submodules are currently supported in TypeScript only. Support for Rust, C#, and C++ is coming soon." C++/C# only got autogenerated `RawSubmoduleV10` types.
  - **Needs a 2.8.0+ server.** Modules that use submodules can't publish to older servers (notes' compatibility note).
  - Lifecycle reducers (`init`, `clientConnected`, `clientDisconnected`) are only allowed in the root module. A submodule that declares one makes publish fail (`ValidationError::LifecycleInSubmodule`).
  - A submodule's own `httpRouter` is ignored. Its handlers must be re-registered on the root router.
  - It's code reuse via normal npm/workspace imports. There is no package registry or marketplace of modules.
  - **Don't show `/` as the separator** (`myauth/verify_token`). The 2.8.0 docs said `/` but the code splits on `.`, and the docs were corrected in v2.8.3 (#5732). The same docs fix renamed `ReducerContext`/`ProcedureContext` in the examples to `ReducerCtx`/`ProcedureCtx`. Use `ReducerCtx` if showing a type.
  - The exact argument format for `spacetime call` (a JSON value per positional argument vs an object) isn't verified. Avoid showing args, or run it first.
- Sources: #5486 (87907691c0); `v2.8.0:docs/docs/00200-core-concepts/00100-databases/00600-submodules.md`; `v2.8.0:crates/schema/src/def.rs` (~619-731), `crates/schema/src/def/validate/v10.rs` (~338-370), `crates/sql-parser/src/parser/mod.rs`, `crates/cli/src/subcommands/call.rs`; #5732 (docs separator fix, v2.8.3); release note: "TypeScript modules can now import and mount other modules under a namespace…".

### Web apps reconnect by themselves when you come back to the tab: MEDIUM (v2.7.1)
- What changed (exact, verified): the TS SDK's `ConnectionManager` (`crates/bindings-typescript/src/sdk/connection_manager.ts`) listens in the browser for `visibilitychange`, `focus`, `online` and `pageshow` (bfcache restores). On resume it checks each retained connection. A reconnect whose backoff timer stalled while the tab was in the background fires immediately with the backoff reset, and a socket that died silently (readyState CLOSING/CLOSED without `onclose`) is torn down and rebuilt.
- Before this range: auto-reconnect with exponential backoff already existed in `ConnectionManager` for React and Solid (and Svelte since 2.7.0). What was missing was recovery after background tabs, sleep or network loss, where timers get throttled and sockets die silently (issue #5524).
- Headline idea: "Back to the tab. Back online."
- One-sentence description: When a user returns to a backgrounded tab or their Wi-Fi comes back, SpacetimeDB web apps now notice right away and reconnect on their own.
- Visual idea: a browser window with a live multiplayer board. The laptop lid closes (screen dims, Wi-Fi icon goes grey, clock jumps +20 min). The lid opens: in the "before" version a stale "Reconnecting in 32 s…" spinner sits there. In the "after" version the connection dot flashes red → green instantly and rows update. Or a timeline showing `visibilitychange → rebuild socket → live`.
- Caveats (don't claim):
  - It only applies to apps using the framework providers built on `ConnectionManager`: **React, Solid and Svelte** (`src/react|solid|svelte/SpacetimeDBProvider.ts`). A bare `DbConnection.builder()` app, Vue or Angular doesn't get it.
  - Browser only (listeners are registered only if `window`/`document` exist). Not Node/SSR, and not the Unity/Unreal/C#/Rust SDKs.
  - It isn't new auto-reconnect as such, only faster and more reliable recovery on resume. The server keep-alive (15 s ping, 30 s idle timeout) already reaped half-open connections in the foreground.
  - Don't claim the identity/session is preserved across the reconnect. A later release (2.9) has "TS identity kept across auto-reconnect", which suggests it wasn't guaranteed here.
- Sources: #5525 (52cf43427a); `v2.8.0:crates/bindings-typescript/src/sdk/connection_manager.ts` lines ~105-125; release note (v2.7.1) "TypeScript SDK reconnects on refocus and network return".

### Scheduled reducers stop drifting (partial fix): LOW (v2.7.1)
- What changed (exact, verified): for repeating schedules, the next run of a scheduled reducer/procedure is now computed from the reducer's own `timestamp` (the start of the run) instead of `Timestamp::now()` after it finished (`crates/core/src/host/scheduler.rs`). Long-running interval reducers no longer drift by their own execution time each run.
- Before this range: the drift came back in #5095 (2026-05-27, first released in **v2.4.0**). It had been fixed once before in #3657. So 2.7.0 users had it.
- Headline idea: "Every tick, on time."
- One-sentence description: Repeating scheduled reducers now keep their rhythm instead of slowly slipping later by however long each run takes.
- Visual idea: two metronome timelines. "Before": ticks at 0, 1.2, 2.4, 3.6 s for a 1 s interval with 200 ms work, so the gaps grow. "After": ticks hold at 1 s spacing.
- Caveats: **not a complete fix.** v2.8.3 (#5735) later re-anchored schedules to the *intended* time, since `tokio` timer precision and head-of-line blocking still caused drift. Don't say "zero drift" in a 2.8 video. Probably better as a list line.
- Sources: #5574 (3beda8791d); `git log -S "Ok(Some((_timestamp, _instant, params)))"` shows #5095 introducing it and #5574 removing it; v2.8.3 notes for #5735.

### Scheduled-function delay warning: LOW (v2.8.0)
- What changed (exact, verified): when a scheduled function starts later than a threshold, the server logs `scheduled function `{name}` for database {id} is delayed by {x}s, exceeding the {t}s threshold` (`log::warn!`, host log). It also records the Prometheus histogram `spacetime_scheduled_function_delay_seconds` (labels `db`, `function`).
- Caveats: the **threshold is 30 ms in code** (`SCHEDULED_FUNCTION_DELAY_WARNING_THRESHOLD = Duration::from_millis(30)`), not the 50 ms stated in the release notes. It goes to server/host logs and metrics, not to the module's `spacetime logs` output (as far as I can tell). Operator-facing only.
- Sources: #5592 (8e5510bf83); `v2.8.0:crates/core/src/host/scheduler.rs` line 194; `crates/core/src/worker_metrics/mod.rs` line ~537.

### Bug fixes worth a list line: LOW
- TS modules: `filter()`/`delete()` on a composite btree index where the last argument is a `Range` (a fixed prefix plus a range on the final column) returned wrong rows, because range bounds were sliced from the start of the key instead of after the prefix [#5479, v2.8.0; issue #5454]. It complements 2.7.0's one-column-prefix fix (#5428).
- Adding a sequence (auto-inc) to an existing integer column: the precheck could wrongly pass (u64::MAX overflowed to -1, and an exclusive upper bound) and then fail later with a unique-constraint violation. It now fails in the precheck [#5561, v2.7.1]. This is a long-standing bug (the precheck dates from 2024).
- V10 schema output (`GET /v1/database/:x/schema?version=10`, `extract-schema`) now includes column default values (they were dropped), which matters for codegen, diff and migration tooling [#5508, v2.7.1].
- A failed module init (e.g. replay error) no longer leaks a metrics task, and there's a new `module_host_init_attempts` counter [#5601, v2.7.1]. Server-internal.

## Open doubts
1. **Range choice**: I used `v2.7.0-hotfix3` (published 2.7.0) as the base, not the literal `v2.7.0` tag. See the range note.
2. **HTTP/2 and CORS preflight caching** (v2.7.1 notes) aren't in this repo. If they're Maincloud-only infra, they could be claimed only as "Maincloud: …" and not for self-hosted servers. Ask the release owner before using them.
3. The submodule call separator: the code at v2.8.0 splits on `.`, and the v2.8.0 docs showed `/` (fixed in v2.8.3, #5732). I didn't run a live call. If the scene shows a terminal, run `spacetime call <db> myauth.verify_token …` against a 2.8 server first to capture the real output and argument format.
4. The scheduled-delay warning threshold is 30 ms in code vs 50 ms in the release notes. The code wins, but it's operator-only anyway.
5. #5525 scope: I confirmed only React/Solid/Svelte providers use `ConnectionManager` at v2.8.0 (`git grep ConnectionManager`). If the video shows a framework, pick one of those three.
